## 1. 背景と目的

### 1.1 背景

発注者はエンジニア。妻(平日9:30〜最長21:00頃まで出社)とトイプードル1匹と暮らす。基本リモート勤務(週1水曜出社)、5:00〜6:00起床、21:30〜22:30就寝。健康志向で、週2回以上のノルウェー式HIIT、16時間の断続的断食、Garmin Venu 4によるライフログ計測を実践。英語学習を3年継続中(毎日の英会話+TOEIC学習1〜4時間、現在スコア650)。

**主要な痛み**: 英語学習の時間が「仕事の長時間化による枠の侵食」「疲労による集中力低下」「会議・家事・犬の世話による割り込み」の複合要因で確保できない。また、健康・学習データがGarminアプリ等に分散し全体像が見えない。

### 1.2 本アプリの位置づけ

本アプリは**技術勉強会での発表(約1ヶ月後)を第一目的**とし、Convex + TanStack Start の技術特性を最大限に示すデモアプリであると同時に、発注者夫婦が実生活で使える実用アプリでもある。

**優先順位: (1) Convexの特性を活かすこと > (2) 生活課題の解決。** ただし両者は設計上両立させる。

### 1.3 Convexの特性を活かす設計原則(最重要)

アプリ全体を「記録の保存庫」ではなく**「生きた状態(live state)の集合」**として設計する。状態変化の駆動源を4種類用意し、それぞれを機能に1対1で割り当てる:

| 駆動源                       | 担当機能                              | 見せるConvex機能                                 |
| ---------------------------- | ------------------------------------- | ------------------------------------------------ |
| 自分(人間の操作)             | 学習ライブセッション                  | リアクティブクエリ、マルチデバイス即時同期       |
| 時間(サーバ側の時限遷移)     | 断食ステートマシン                    | scheduled functions によるサーバ側状態遷移       |
| 他人(別ユーザーの操作)       | 犬のクイックアクション+ステータス共有 | 2ユーザー間のリアルタイム伝播                    |
| 外部(外部システムからの流入) | Garminデータ自動取得                  | cron jobs / actions("use node")による外部API連携 |

さらに導出値(join・集計)のリアクティブ再計算を「相関ビュー」で示す。

## 2. ユーザーとロール

| ロール      | 人物   | 主な利用                                                                         |
| ----------- | ------ | -------------------------------------------------------------------------------- |
| self(本人)  | 発注者 | 全機能。学習セッション・断食・HIIT・健康データの主体                             |
| partner(妻) | 配偶者 | ライブボード閲覧、犬のクイックアクション、自身のステータス更新(出社中/帰宅ETA等) |

- 主要ユーザーはこの2名(self / partner)。**v1.1改訂: サインアップは開放**し、登録時に role を自己選択する(FR-9.3)。招待フロー・チーム機能は作らない。
- 犬(トイプードル)はユーザーではなくエンティティ。犬のプロフィール(名前・写真)は設定で保持。
- デモ時は発表者が2ブラウザ/2端末で self / partner 両方を操作できること(=デモ用に partner アカウントへ発表者がログイン可能)。

## 3. 利用シナリオ(実生活)

- S1 朝(5:30): 本人が起床。ダッシュボードに昨夜の睡眠スコアとBody Battery(cronが取得済み)が表示されている。今日の学習枠を宣言(例: 6:00-7:00 TOEIC、13:00-13:30 英会話予習)。
- S2 学習(6:00): PCでセッション開始。タイマーはサーバ状態。犬が騒いだらスマホからワンタップ「中断(犬)」→PC画面も即座に一時停止表示。戻ったら再開。
- S3 断食: 前夜20:00に「断食開始」。16時間後の12:00にサーバ側scheduled functionが「達成」フェーズへ自動遷移し、全端末のUIが操作なしで切り替わる。
- S4 日中: 仕事が長引き13:00の枠が消える → ワンタップで「侵食(仕事)」を記録し、リスケ候補(空き時間帯)から選ぶ。
- S5 夕方: 妻が退社時に自分のステータスを「帰宅中 ETA 20:30」に更新 → 本人のライブボードが即時更新。犬の夜ごはんをどちらがあげるかが「未」表示で一目瞭然。あげた方がワンタップ記録 → もう一方の画面から「未」が消える(二重給餌防止)。
- S6 週次: 相関ビューで「睡眠スコアが高い日ほど学習時間が長いか」「HIIT翌日のBody Batteryと学習集中度」を眺める。

## 4. 機能要件

各要件はID付き。優先度: **P0=MVP必須(発表に必要)** / P1=発表までに入れたい / P2=あれば良い。

### FR-1 ライブボード(ホーム画面)【P0】

- FR-1.1 1画面に「本人カード」「パートナーカード」「犬カード」を表示し、全カードがリアルタイム更新される。
- FR-1.2 本人カード: 現在の学習セッション状態(勉強中○分/中断中/なし)、断食状態(経過h/フェーズ)、今日のBody Battery・睡眠スコア、今日の学習実績/宣言合計。
- FR-1.3 パートナーカード: ステータス(在宅/出社中/帰宅中+ETA/就寝 等)と最終更新時刻。
- FR-1.4 犬カード: 今日のケア項目(朝散歩/夜散歩/朝ごはん/夜ごはん/薬 等)の済・未と、実施者・時刻。
- FR-1.5 ボードは self / partner どちらのアカウントでも同一内容を閲覧可能(視点によるカード並び替えは任意)。
- FR-1.6 デモ要件: 2端末で並べたとき、一方の操作がもう一方に体感即時(<1s)で反映されること。

### FR-2 学習ライブセッション【P0】

- FR-2.1 セッションはサーバ側ドキュメントとして状態を持つステートマシン(idle → active ⇄ paused → completed / abandoned)。
- FR-2.2 開始時にカテゴリ(英会話/TOEIC/読書 等)と任意の目標分数を指定できる。宣言済みの学習枠(FR-3)に紐づけ可能。
- FR-2.3 経過時間はクライアントのローカルタイマーではなく、サーバ保存の `startedAt / accumulatedMs / lastResumedAt` から導出する(全デバイスで同一値になる)。
- FR-2.4 中断はワンタップで理由(仕事/犬/家事/その他)を記録。中断・再開・完了はどのデバイスからでも操作でき、他デバイスへ即時反映。
- FR-2.5 アクティブなセッションは同時に1つまで。既存アクティブがある状態での開始は拒否またはそのセッションへ誘導。
- FR-2.6 完了時に実績分数・中断回数・中断内訳が確定保存される。
- FR-2.7 放置対策: アクティブのまま長時間(既定6h)経過したセッションはscheduled functionでabandonedに自動遷移(サーバ側時限遷移の実例その2)。
- FR-2.8 **(v1.3 追加)** 過去セッションの履歴(過去日)を簡易リストで閲覧できる(P1)。日付ごとにカテゴリ・実績分数・中断回数・最終状態(completed/abandoned)を表示。**補足(v1.4)**: 中断回数には要因の内訳(例: 犬×2 · 仕事×1、interruptions テーブルの join 導出)を併記する。編集・削除は不要(FR-5.4 の犬ケア履歴と同じ粒度)。表示場所は `/study` ルート。

### FR-3 学習枠の宣言と防衛(Lv2)【P0】

- FR-3.1 日単位で学習枠(開始・終了時刻、カテゴリ、予定分数)を複数宣言できる。
- FR-3.2 枠は planned → done(セッション実績と紐づけ) / eroded(侵食: 理由=仕事/疲労/割り込み/その他) / rescheduled / declined のいずれかに遷移。
- FR-3.3 侵食時、当日の残り時間帯からリスケ候補を提示し、選択で新枠を生成(元枠とのリンクを保持)。
- FR-3.4 「宣言 vs 実績」の当日サマリがライブボードに出る(パートナーからも見える=緩い社会的コミットメント)。
- FR-3.5 スキーマに `source: "manual" | "suggested"` を持たせ、将来のカレンダー/AI提案(Lv3)への拡張余地を残す。
- FR-3.6 **(v1.5 追加)** `/study` の枠宣言は開始日時・終了日時の DateTimePicker で、今日以降の同日範囲のみ作成できる。未来日の planned 枠は「予定」セクションに今日超〜30日先まで表示し、planned の間だけ編集・物理キャンセルできる。カレンダー上の日本の祝日は選択可能なまま祝日名付きで強調表示し、土曜は青、日曜・祝日は赤で表示する。
- FR-3.7 **(v1.6 追加)** 侵食時のリスケ候補提示に「リスケしない」ボタンを追加し、確認ダイアログ(Mantine ConfirmDialog)を経て枠を declined(見送り)に遷移できる。declined は取り消し可能で、「元に戻す」操作で eroded に戻し再度リスケ候補から選び直せる。理由の記録は行わない(FR-3.2 の erosionReason で既に記録済みのため)。

### FR-4 断食ステートマシン【P0】

- FR-4.1 「断食開始」で eating → fasting。目標時間は既定16h(変更可)。**補足(v1.2)**: 目標分数(`targetMinutes`)は断食開始のたびに任意指定できる。省略時は `appSettings.fastingDefaultMinutes`(既定960分=16h)を使う。AC-2 のデモ短縮(分単位設定)は、開始時にこの値を短く指定するだけで実現する(専用の隠し設定画面は不要)。
- FR-4.2 フェーズ遷移(例: fasting開始 → 12h「脂肪燃焼帯」→ 16h「目標達成」)は**クライアントのポーリングではなくConvex scheduled functionがサーバ側でドキュメントを書き換える**ことで発生し、全購読クライアントのUIが自動で切り替わる。
- FR-4.3 「食事開始(断食終了)」で実績時間を確定し、予約済みの未来遷移ジョブをキャンセルする。**補足(v1.2)**: 断食中(`status:"fasting"`)でない状態での終了操作は無視/エラーとする(FR-2 の二重操作ガードと同じ方針)。
- FR-4.4 ライブボードとセッション画面に経過時間・現フェーズ・目標までの残りを常時表示。

### FR-5 犬のクイックアクション【P0】

- FR-5.1 定義済みケア項目(朝散歩・夜散歩・朝ごはん・夜ごはん・薬・トイレ・その他)をワンタップで「実施」記録(実施者・時刻自動付与)。
- FR-5.2 記録・取り消しは両ユーザーから可能で、相手の画面に即時反映。
- FR-5.3 当日の未実施項目が視覚的に目立つこと(例: 夜ごはん「未」)。二重実施をUIで抑止(済み項目は確認ダイアログ)。
- FR-5.4 履歴(過去日)の閲覧は簡易リストで良い(P1)。

### FR-6 健康データ(Garmin)流入【P0(手動+デモ) / P1(実連携)】

- FR-6.1 日次メトリクス: 睡眠スコア、睡眠時間、Body Battery(起床時値または最大値)、HRV、安静時心拍、歩数。対象は本人のみ。
- FR-6.2 手動入力UI(フォールバック): 朝にGarminアプリの値を転記できる。source="manual"。**補足(v1.2)**: 同日の再入力は新規行を増やさず upsert(上書き)する(`healthMetrics.by_date` を patch)。全項目(睡眠スコア・睡眠時間・Body Battery・HRV・安静時心拍・歩数)は任意入力で、分かる値だけ埋めれば良い。
- FR-6.3 実連携: 非公式 `garmin-connect-sdk`(npm、`1.0.0-alpha.4` に完全固定)を用い、Convexの "use node" action + cron(毎朝、JST 6:30目安)で自動取得。source="garmin"。認証情報/トークンはConvex環境変数に保存。取得失敗はsyncLogsに記録し、UIに「最終同期」表示。**改訂(v1.7)**: 選定理由 = 依存が zod のみ(サプライチェーン最小)・MFA 正式対応(`login({email, password, mfaCode})`)・Body Battery/HRV/睡眠の型付きメソッドあり。制約 = Node `>=24` 要件のため `convex.json` で Node 24 を指定する(Convex は 20/22/24 対応・既定 20)。alpha のため自前の薄いラッパー越しに使い、退避先は `@gooin/garmin-connect@1.8.7`。トークンは SDK の `TokenStorage` 抽象に合わせたカスタム実装で環境変数から復元する。
- FR-6.4 **デモモード**: 設定でONにすると、cron/インターバルジョブが数十秒間隔で疑似メトリクス(source="demo")を流し込み、誰も操作していないのにダッシュボードのグラフが動く様子を見せられる。デモデータは実データと分離され、一括削除できる。**補足(v1.2)**: 間隔は既定20秒(NFR-5 の ≥15秒を満たす)。「一括削除」は専用ボタンを設けず、デモモードを OFF にした時点でジョブのキャンセルと `source="demo"` 行の削除を自動で行う。
- FR-6.5 HIIT記録: 種別(HIIT等)・実施時刻・時間・主観強度をワンタップ〜数タップで記録(Garmin activityの自動取込はP2)。

### FR-7 相関ビュー(リアクティブjoin)【P1】

- FR-7.1 直近N日(既定28日)について「睡眠スコア×当日学習分数」「Body Battery×学習分数」「HIIT実施翌日のBody Battery」を散布図/バーで表示。
- FR-7.2 集計はConvexクエリ内で複数テーブルをjoinして導出し、**元データの追加・変更で自動再計算・再描画**されること(発表のコード解説パートの題材)。
- FR-7.3 統計的厳密性は不要。単純な散布図+相関係数程度で良い。

### FR-8 パートナーステータス【P0】

- FR-8.1 妻が自分の状態(在宅/出社中/帰宅中+ETA/外出/就寝)をワンタップ+任意ETAで更新できる。
- FR-8.2 本人のライブボードに即時反映。履歴は当日分のみで良い。

### FR-9 認証・アカウント【P0】

> v1.1改訂(2026-07-06): 発注者判断により「2アカウント事前作成・サインアップ閉鎖」を廃止し、オープンサインアップに変更。

- FR-9.1 認証必須。未認証はログイン画面(`/login`)へリダイレクト。
- FR-9.2 全Convex関数はサーバ側で認証を検証する(クライアント側ガードだけに依存しない)。
- FR-9.3 サインアップ(`/signup`)を開放する。email+パスワード(12文字以上・英大小・数字、確認入力あり)+表示名+ロール(self/partner の自己選択)で登録し、即時有効。パスワードリセット・メール検証はスコープ外。
- FR-9.4 認可: self専用ページ(`/health` `/insights` `/settings`)へ partner ロールがアクセスした場合は `/` へリダイレクトし通知を表示する。対応するサーバ関数も role を検証する(requireSelf)。

## 5. 非機能要件

- NFR-1 リアルタイム性: 同一ネットワーク下の2クライアント間伝播は体感1秒以内(Convex標準性能で満たされる想定。独自最適化は不要)。
- NFR-2 対応環境: 最新Chrome/Safari。スマホはブラウザ表示で良い(ネイティブアプリ不要)。**モバイル幅(375px)とデスクトップの両方でライブボードが破綻しないこと**(デモは2端末並べる)。
- NFR-3 タイムゾーン: すべて Asia/Tokyo 前提。「日付」境界はJSTの0:00(cron定義はUTC変換に注意)。
- NFR-4 セキュリティ: Garmin認証情報はConvex環境変数のみに保持し、クライアントへ送らない。リポジトリに秘密情報をコミットしない。
- NFR-5 コスト: Convex無料枠・個人プランで収まる規模(ユーザー2名、書き込み頻度低)。デモモードの流し込み間隔は乱用しない(≥15s)。
- NFR-6 可用性: 個人アプリのため高可用性要件なし。ただしデモ失敗保険として、主要なリアルタイム同期シーンの録画(GIF/動画)を発表資料に同梱する運用とする。
- NFR-7 保守性: 他のAIモデルが引き継げるよう、`spec.md` の規約(ディレクトリ構成・命名・状態遷移定義)に従うこと。

## 6. スコープ外(明示)

- チャット、タスク/ToDoの汎用管理、カレンダー同期(Lv3)、ネイティブアプリ、プッシュ通知基盤、3人目以降のユーザー向け専用機能(ロールは self/partner の2種のみ。サインアップ自体は開放=FR-9.3)、パスワードリセット・メール検証、犬の健康診断記録、食事内容の栄養管理、TOEIC問題演習機能そのもの(学習「時間」の管理に限定)。

## 8. 受け入れ基準(発表可能の定義)

- AC-1 2ブラウザ(self/partner)を並べ、片方の操作(セッション開始/中断、犬ごはん記録、ステータス更新)が他方に1秒以内に反映される。
- AC-2 断食の16h到達(デモでは短縮設定可: 目標を分単位に変更できる隠し設定を用意)で、**誰も操作していないのに**両画面のフェーズ表示が切り替わる。
